# Two-stage training (SFT → GRPO)

This folder contains the training entry points described in **Sec. 3.2** of the
paper. The exact hyperparameters are taken from **Appendix B**; the scripts are
reference implementations built on [ms-swift](https://github.com/modelscope/ms-swift).

> **Reproduction note.** The released AgentThink checkpoint was trained with the
> pipeline below on the Tool-CoT data generated by this repository. Exact
> bit-for-bit reproduction additionally requires the same base checkpoint, the
> same Agent-Driver perception pickles, and the same generated corpus. Training
> on a different subset will give different scores.

## 0. ms-swift compatibility

The paper uses **ms-swift 3.x** (`swift.llm`, `swift.plugin.ORM`). ms-swift 4.0
restructured the package and removed `swift.llm`, which breaks the inference
scripts in this repository. `scripts/env.sh` therefore installs
`ms-swift[all]>=3.5,<4.0`; the CLI below was checked against **3.5.0** and
**3.12.6**.

| Paper (Appendix B) | ms-swift 3.x flag |
|---|---|
| base model | `--model` |
| LoRA rank / alpha | `--lora_rank 8 --lora_alpha 32` |
| 20 epochs | `--num_train_epochs 20` |
| batch 2 per device | `--per_device_train_batch_size 2` |
| gradient accumulation 16 | `--gradient_accumulation_steps 16` |
| learning rate 1e-4 / 1e-5 | `--learning_rate` |
| bf16 | `--torch_dtype bfloat16` |
| frozen ViT | `--freeze_vit true` |
| max sequence length | `--max_length` |
| evaluate / save every N steps | `--eval_steps` (needs `VAL_DATASET`) / `--save_steps` |
| keep at most 5 / 20 checkpoints | `--save_total_limit` |
| ZeRO-2 / ZeRO-3 | `--deepspeed zero2` / `zero3` |
| warmup ratio | `--warmup_ratio` |
| dataloader workers | `--dataset_num_proc`, `--dataloader_num_workers` |
| no gradient-checkpoint reentrancy | `--gradient_checkpointing true --gradient_checkpointing_kwargs '{"use_reentrant": false}'` |
| GRPO | `--rlhf_type grpo` |
| G = 2 rollouts | `--num_generations 2` |
| temperature 1.2 | `--temperature 1.2` |
| 2048 total / 1024 completion | `--max_length 2048 --max_completion_length 1024` |
| β = 0.001 | `--beta 0.001` |
| paper's system instruction | `--system "You are a helpful assistant. ..."` |
| reward plugin | `--custom_register_path scripts/tools/rewards.py --reward_funcs agentthink_reward` |
| world size | environment variable `NPROC_PER_NODE` (**not** a CLI flag) |

Notes that caused mismatches with a naive port:

- ms-swift launches `torchrun` only when `NPROC_PER_NODE` (or `NNODES`) is set in
  the environment. `--nproc_per_node` is not an ms-swift argument.
- The gradient-checkpointing key is `use_reentrant`, not `reentrancy`.
- Custom rewards are **classes** registered in `orms`, not bare functions. The
  module registers `AgentThinkReward` automatically on import.

## 1. What each stage trains

| Stage | Data | Objective | Paper |
|---|---|---|---|
| SFT phase 1 | `agentthink_sft_phase1.jsonl` | emulate reasoning steps **and** tool calls; tool outputs hidden | Eq. 2, Sec. 3.2.1 |
| SFT phase 2 | `agentthink_sft_phase2.jsonl` | same, with real tool observations in the context | Eq. 3 |
| GRPO | `agentthink_grpo.jsonl` | optimize final-answer, step-reasoning and tool-use rewards | Eq. 4–7, Table 1 |

## 2. Hardware

The paper reports **16 × NVIDIA A800 (80 GB)** for the full run. The table below
is practical guidance derived from the memory footprint of each stage; only the
16-GPU configuration is the one used in the paper.

| Stage | Minimum | Recommended | Notes |
|---|---|---|---|
| Inference (merged 7B) | 1 × 80 GB | 1 × 80 GB | `evaluation/inference*.py` |
| SFT (LoRA) | 2 × 80 GB | 8 × 80 GB | per-device bs 2 × grad-accum 16, max_len 4096 |
| GRPO | 4 × 80 GB (reduced) | 8–16 × 80 GB | 2 rollouts/question, generation is the bottleneck |

For a 24 GB GPU, SFT is possible with `--max_length 2048`,
`--per_device_train_batch_size 1`, `--gradient_accumulation_steps 32` and
ZeRO-3, but this configuration is not validated. GRPO is not recommended below
4 × 80 GB because the policy and the rollout engine must coexist in memory.

All commands accept `NPROC_PER_NODE` (SFT/GRPO) to change the world size:

```bash
NPROC_PER_NODE=4 bash training/sft.sh phase1
```

## 3. Build the training data

The following assumes `data/tool_results/cot_val_Qwen2.5-VL.json` was produced by
the data-generation pipeline (`scripts/tools/agentthink_data_generater_pipeline.py`
→ `scripts/tools/gen_tool_result_data.py`). The same file also builds the
evaluation JSONL (see `docs/pipeline.md`).

```bash
# SFT phase 1: actions only, tool observations masked
python scripts/tools/build_sft_data.py \
    --input data/tool_results/cot_val_Qwen2.5-VL.json \
    --output data/agentthink_sft_phase1.jsonl \
    --format agentthink --target sft --no-observations

# SFT phase 2: reasoning + tool observations
python scripts/tools/build_sft_data.py \
    --input data/tool_results/cot_val_Qwen2.5-VL.json \
    --output data/agentthink_sft_phase2.jsonl \
    --format agentthink --target sft

# GRPO prompts: no assistant turn, reference answer and key steps as columns
python scripts/tools/build_sft_data.py \
    --input data/tool_results/cot_val_Qwen2.5-VL.json \
    --output data/agentthink_grpo.jsonl \
    --format agentthink --target grpo
```

If you only want to warm up on the released reference CoT (no tool traces), use
`scripts/tools/prepare_swift_data.py` instead.

## 4. Run

```bash
export PYTHONPATH=$PWD
export VAL_DATASET=data/agentthink_val.jsonl   # optional

# Phase 1
bash training/sft.sh phase1 data/agentthink_sft_phase1.jsonl outputs/sft_phase1

# Phase 2 (initialise from the phase-1 adapter)
ADAPTERS=outputs/sft_phase1/v2-*/checkpoint-* \
  bash training/sft.sh phase2 data/agentthink_sft_phase2.jsonl outputs/sft_phase2

# GRPO from the phase-2 adapter
ADAPTERS=outputs/sft_phase2/v2-*/checkpoint-* \
  bash training/grpo.sh Qwen/Qwen2.5-VL-7B-Instruct \
    data/agentthink_grpo.jsonl outputs/grpo

# Merge the final adapter for inference
bash training/merge_lora.sh outputs/grpo/v2-*/checkpoint-* pretrained_model/AgentThink
```

GRPO weights can be changed without editing code:

```bash
AGENTTHINK_REWARD_WEIGHTS="0.4,0.3,0.3" bash training/grpo.sh ...
```

## 5. Reward functions

`scripts/tools/rewards.py` implements Table 1:

| Reward | Function | Sub-scores |
|---|---|---|
| Final answer | `final_answer_reward` | exact match / token F1, option-label match for MCQ |
| Step reasoning | `step_reasoning_reward` | key-step coverage with an ordering bonus (0.7) + chain coherence (0.3) |
| Tool use | `tool_use_reward` | format compliance (0.4) + integration quality (0.6) |
| Combined | `agentthink_reward` | weighted sum, default `0.4 / 0.3 / 0.3` |

Both serialisations are supported: the structured Tool-CoT JSON and the text
trace rendered by `chain_render.py` (`Step N: ... / Tool: name(...)`).

The reward functions are pure Python and unit-tested in `tests/test_rewards.py`.

## 6. Practical tips

- Generation during GRPO is the dominant cost. Lower `--max_completion_length`
  before lowering `--num_generations`; the latter changes the advantage estimate.
- Keep `--temperature 1.2` as in Appendix B.2, otherwise the two rollouts become
  too similar and the group advantage collapses to zero.
- Save adapters every 100 steps and evaluate the merged checkpoint with
  `evaluation/evaluation_script.py --limit 50` before running the full judge.
