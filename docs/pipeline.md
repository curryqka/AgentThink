# AgentThink pipeline: artifacts and commands

This document is the contract between the paper (Sec. 3) and the code. It lists
every artifact, which script produces it, and which script consumes it.
Questions in issues #5/#6 ("where does `tool_result` come from?", "how do I
reproduce 71.35 MCQ?") are answered at the end.

## 0. Overview

```
                 nuScenes images              DriveLMM-o1 QA json
                        │                             │
                        ▼                             ▼
  (1a) tool-CoT generation  ──►  final_cot_<split>_<model>.json
                        │
  (1b) six-view collage ────────►  data/image2concat/<scene_frame>.png
                        │
  (1c) execute tool chains ─────►  cot_val_Qwen2.5-VL.json  (tool_result, system_prompts)
                        │
  (1d) JSONL conversion ────────►  data/DriveLMMo1_TEST_tool_results.jsonl
                        │
  (1e) SFT/GRPO builder ────────►  data/agentthink_{sft_phase1,sft_phase2,grpo}.jsonl
                        │
                        ▼
  (2) SFT → GRPO (training/)  ──►  LoRA adapter ──► merged checkpoint
                        │
                        ▼
  (3) inference (three modes) ──►  results/*.json
                        │
                        ▼
  (4) LLM-as-Judge (evaluation/) ─►  *.summary.json / *.csv
```

## 1. Data generation (paper Sec. 3.1)

### 1a. Generate structured Tool-CoT with GPT-4o

```bash
export OPENAI_API_KEY=...
python scripts/tools/agentthink_data_generater_pipeline.py \
    --input data/DriveLMMo1/DriveLMMo1_TRAIN.json \
    --split train --model-name gpt-4o-mini \
    --output final_cot_train_gpt-4o-mini.json
```

Produces, per sample, a `cot_data` object with `Chain[i] = {Tool, Sub,
Guess_Answer, key_words, Missing_flag, next_action}` and a final answer.
Resume support: `--progress-file`; a rerun continues from the last index.

### 1b. Build the six-view collage

```bash
python scripts/tools/data_image_converter.py \
    --json-file-path data/DriveLMMo1/DriveLMMo1_TEST.json \
    --image-root-dir /path/to/nuscenes \
    --savepath-img data/image2concat
```

The output filename is `<idx without the question suffix>.png`, e.g.
`e7ef...b10f....png`. Both training and evaluation resolve images this way.

### 1c. Execute the planned tools

```bash
python scripts/tools/gen_tool_result_data.py \
    --input final_cot_train_gpt-4o-mini.json \
    --output data/tool_results/cot_val_Qwen2.5-VL.json \
    --tool-data-path data/tool_results --split val
```

> **This is the step that produces `tool_result`.** Tool observations are *not*
> generated by the VLM. They are the returns of the driving tools executed on
> the [Agent-Driver](https://github.com/USC-GVL/Agent-Driver) perception pickles
> (`data/tool_results/{val,train}/<frame_token>.pkl`). `system_prompts` contains
> the ego-state description. If the pickles are missing for a frame, the sample
> is skipped.

### 1d. Convert to the evaluation JSONL

```bash
python evaluation/prepare_data.py \
    --input data/tool_results/cot_val_Qwen2.5-VL.json \
    --output data/DriveLMMo1_TEST_tool_results.jsonl
```

Fields: `id`, `image`, `conversations` (question / final answer / reference
steps), `tool_result`, `system_prompts`. The plain test set
`DriveLMMo1_TEST.jsonl` (no tool fields) is built by the same script from the
raw `DriveLMMo1_TEST.json` or shipped with the release.

## 3. Inference (paper Sec. 3.3)

Three scripts, three different questions:

| Script | Input | What the model does | Output |
|---|---|---|---|
| `evaluation/inference.py` | `DriveLMMo1_TEST.jsonl` | plain CoT answer | answer text |
| `evaluation/inference_withtool.py` | `DriveLMMo1_TEST.jsonl` + tool catalog | plans a Tool-CoT chain | `tool_chain` JSON + validation |
| `evaluation/inference_agentthink.py` | `DriveLMMo1_TEST_tool_results.jsonl` | answers with retrieved tool observations | answer text |

```bash
CKPT=pretrained_model/AgentThink

# Baseline
bash scripts/inference_scripts/inference.sh "$CKPT" qwen7b_cot

# Structured tool planning (no execution)
bash scripts/inference_scripts/inference_withtool.sh "$CKPT" toolcot

# Full AgentThink
bash scripts/inference_scripts/inference_agentthink.sh "$CKPT" AgentThink
```

All three accept `--limit` for a smoke test and `NPROC_PER_NODE`/`torchrun` for
multi-GPU. Plain `python evaluation/inference.py ...` also works (single GPU).

> `inference_withtool.py` deliberately does **not** answer the question: it
> emits the structured plan that `gen_tool_result_data.py` can execute. If you
> feed its output to the judge directly you will see plain-CoT-style text from
> an untrained checkpoint and a low `format_valid` rate. Check the printed
> "Schema-valid tool chains" line first.

## 4. Evaluation (paper Sec. 3.3, Table 2)

```bash
export OPENAI_API_KEY=...
python evaluation/evaluation_script.py \
    --input results/agentthink/DriveLMMo1_AgentThink.json \
    --dataset data/DriveLMMo1/DriveLMMo1_TEST.json \
    --output results/agentthink_eval \
    --tool-metrics
```

Outputs `*.json` (per sample), `*.csv`, and `*.summary.json` with the seven
columns of Table 3 (`Risk Assess.`, `Rule Adh.`, `Scene Aware.`, `Relevance`,
`Missing`, `Reason.`, `MCQ`) plus the three tool metrics of Table 5 when
`--tool-metrics` is set.

Cost control: `--limit 50` first; the judge is the only paid component.

## 5. Reproduction checklist (issue #6)

1. **Use the released merged checkpoint**, not the base Qwen2.5-VL model:
   `pretrained_model/AgentThink` must contain `config.json` + weights.
2. **Images**: six-view collage, 3 × 2, at `data/image2concat/<stem>.png`.
   A single camera image silently changes the task.
3. **Tool results**: JSONL must contain `tool_result` with non-empty `prompt`
   fields. `--tool-result-style repr` reproduces the v1 behaviour, `prompts`
   (default) is the intended one.
4. **Question/answer parsing**: `evaluation_script.py` extracts the answer after
   `**Final Answer**:`. A truncated generation (`--max-new-tokens` too small)
   loses the answer and tanks MCQ.
5. **Judge**: GPT-4o-mini, temperature 0, the schema in
   `evaluation/prompts.py`. Judge drift is ±1-2 points; MCQ is deterministic
   given the answers, so use MCQ as the reproduction signal.
6. **Sanity numbers**: base Qwen2.5-VL-7B MCQ 37.81; DriveLMM-o1 62.36;
   AgentThink 71.35. If your base model scores far above 40 on MCQ, you are not
   running the base model.

## 6. FAQ

**Can it run on 2 or 4 A800s (issue #4)?**
Yes for inference (even 1 × 80 GB). SFT works on 4 × A800 with the paper's
settings and on 2 × A800 with `NPROC_PER_NODE=2` plus a smaller
`--max_length`. GRPO is generation-bound; 4 × 80 GB is the practical minimum
with reduced completion length, 8–16 GPUs match the paper. See
[training/README.md](../training/README.md#2-hardware).

**Where are the model and data (issue #2)?**
Links are in the README "Model & data" section. The release contains the merged
AgentThink checkpoint, the DriveLMM-o1 test JSONL files and the Tool-CoT data.
Hugging Face mirrors are tracked in issue #2; the repository does not contain
weights.

**Why is `DriveLMMo1_TEST_tool_results.jsonl` different from the model output
(issue #5)?**
Because it is not model output: `tool_result` = executed tool observations,
`system_prompts` = ego states. See step 1c.

**Why does `inference_demo_*.py` read a fixed tool list from the demo JSON?**
The demos illustrate the runtime tool interface without requiring a trained
planner. For end-to-end planning use `inference_withtool.py` →
`gen_tool_result_data.py` → `inference_agentthink.py`.
